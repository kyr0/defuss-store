defuss-store is a small, synchronous observable store with path writes, selectors and computed values. Persist what must survive a reload to localStorage or sessionStorage - validated, versioned, and with unreadable bytes left untouched for you to recover - and bind it to any defuss-shadcn component. Plain JavaScript or TypeScript, with or without defuss.

Try the live demo Read the API

Built by Aron Homberg (kyr0) (opens in a new tab) – Open Source (MIT (opens in a new tab))

Synchronous, in order

set() has committed state when it returns. Listeners run first in, first out; one that throws does not stop the others, and the errors arrive together as one AggregateError.

Bad bytes stay put

Unparsable JSON, a value your validator rejects or a future schema version pauses writes and keeps the stored bytes. You can recover explicitly: rehydrate(), flush() or clear().

Validated and versioned

A validator is mandatory on every read and write. A schema version plus migrate() upgrades old data, and the migrated value is validated again.

In sync across tabs

sync: true follows native storage events: another tab's write arrives without echoing back. Whole-value, last write wins.

The backbone of every JS-based defuss-shadcn component

defuss-shadcn keeps each component's state in a defuss-store store, el.store is accessible from the DOM element. defuss-store's API is exposed via df$.store and bindState() can be used to tie your own stores to any State API.

Small, and safe on servers

The core is 1.9 kB gzip, every layer 4.7 kB, with zero dependencies. Importing it touches no window, document or storage.

How it works

💡 One store commit() - consistency follows

A write compares, installs the new snapshot and queues one transition. Listeners drain in order; persistence is one of them, so the value is validated and stored before set() returns. Other tabs read the new bytes from their own storage event.

What a reload finds

  • restored

    Valid bytes of the current version are in memory when attachPersistence() returns, and writes resume.

    phase: 'active'
  • migrated

    Data of an older version goes through migrate(old, fromVersion), is validated, and stays dirty until the next save.

    dirty: true
  • missing

    Nothing is stored: memory keeps its defaults and nothing is written until something changes.

    hasStoredValue: false
  • paused

    Bad JSON, a rejected value or a future version: the bytes stay untouched and automatic writes pause.

    phase: 'paused', lastError

Recovery is explicit

  1. 01

    rehydrate()

    Read the key again after fixing it; saved state wins, a missing key keeps memory.

  2. 02

    flush()

    Validate and save what is in memory, replacing the bad bytes on purpose.

  3. 03

    clear()

    Remove only this key. Memory keeps its state; the next change writes again.

With or without defuss

🔌 Plain JavaScript first, defuss when you want it

The store library doesn't require any specific framework to be integrated with. In a web app that uses defuss-shadcn, it is already loaded, as df$.store is populated and as every JS component's API exposes el.store, setState() and getState() as well as render() to re-render after state change.

Without defuss

Any app, any bundler or none.

  • npm install defuss-store, then import defuss-store, /storage, /persist or /bind - each layer alone.
  • Or one file in the browser: dist/browser.js bundles every layer and imports nothing.
  • Node 22.12+ for SSR; declarations for TypeScript; ESM only.
  • Use the raw API directly.

With defuss

defuss-shadcn pages and defuss apps.

  • defuss-shadcn's core.js ships it as df$.store.create, computed and persisted.
  • Every component's state is a store: el.store.subscribe() sees clicks and Escape, el.store.set() drives it.
  • bindState() ties your own (persisted) store to any component's State API.
  • In defuss JSX, subscribe in onMount and unsubscribe in onUnmount.
API

📚 Small API surface

Five exported package entrypoints, each importable on it's own. The source of truth is the README (opens in a new tab) and src/types.ts (opens in a new tab).

createStore(initial, { equals? }) returns a writable store. Equality is Object.is by default: an equal write keeps the old reference and notifies nobody.

MemberBehavior
.value, .get(), .getRaw()The current snapshot, by reference. Treat it as immutable: mutating it in place is not observed.
.get('field')A known top-level key keeps its TypeScript type.
.get('items[0].name')A dynamic path returns unknown; own properties only.
.set(next), .setRaw(next)Replace the root, including null or undefined when T allows it.
.set(path, next)Copy the touched ancestors, keep every other reference. Dot or bracket paths: items.0.name, items[0].name.
.remove(path), .set(path, undefined)Delete an object property or splice an array index.
.update(fn)Replace with fn(current), synchronously. A throwing updater changes nothing.
.reset(), .reset(next)Restore the initial reference (not a deep clone), or replace with the explicit argument.
.subscribe(listener, { immediate? })Receives (next, previous, changedPath); returns an idempotent unsubscribe.
.subscribe(selector, listener, { equals?, immediate? })Notifies only when the selected result changes.
.onDestroy(cleanup), .destroy()Register cleanup; destroy idempotently. The last snapshot stays readable.
Reentrant writes and listener errors

A write inside a listener commits at once; its notification is queued and the queue drains first in, first out. While an earlier callback runs, .value can already hold a later value - use the callback's next argument. Removed listeners are skipped; new ones see only later commits. Listener errors do not stop other listeners or persistence: an AggregateError is thrown after the queue drains. There is no rollback or transaction API.

Paths

Paths work on plain objects and arrays with nonnegative indices. Empty writes, malformed paths, inherited traversal and the segments __proto__, prototype and constructor are rejected before anything changes. Dynamic path setters are not compile-time schema validation; prefer a typed update() for that.

computed(source, project, { equals? }) and computed([a, b] as const, (a, b) => result) return a read-only store.

attachPersistence(store, { key, storage, version, validate, migrate?, legacyVersion?, codec?, hydrate?, sync?, onError? }) returns a controller. One controller owns a store at a time; destroying the store disposes it.

Option / methodContract
hydrate: 'immediate' (default)Read and validate before automatic writes start.
hydrate: 'manual'Writes and remote reads wait for rehydrate(), flush() or clear().
hydrate: 'skip'Writes on, no read; nothing is written until a change or flush().
migrate(old, fromVersion)Returns the current schema; its output is validated. Future versions are never downgraded.
sync: trueFollows the selected area's storage events for this key; rereads the current bytes and never echoes.
rehydrate()Read again: saved state wins, a missing key keeps memory.
flush()Validate and save memory; recovers paused persistence on purpose.
clear()Remove only this key; the next real change may write it again.
status(){ phase, dirty, hasStoredValue, lastError? }
destroy()Unsubscribe without writing or deleting; never flushes implicitly.
The stored envelope

{ "format": "defuss-store", "formatVersion": 1, "version": 1, "value": … }. The schema version is a nonnegative safe integer. Raw JSON from the old defuss store is read through legacyVersion and rewritten in the envelope on the next write.

Errors and quota

rehydrate(), flush() and clear() return true on success and false on a reported failure. A write or quota error keeps the committed memory, marks it dirty and reports through onError; the next change or flush() retries. Without onError, failures go to console.error.

bindState(element, store, { select, toState, fromState, ... }) binds one store selection to a component's State API, both ways. It returns a callable disposer with pull() and push().

OptionContract
select, toState, fromStateThe slice this component owns, how it becomes a component state, and how the effective state goes back into the store.
initial'store' (default) applies the store to the element; 'element' reads the element first.
equalsSelection equality in both directions; it is what stops pushes and observations from echoing.
signalAborting releases everything, like calling the disposer or destroying the store.
events, observe, sources, onErrorExtra component events, the mutation observer, which change sources count, and errors of coalesced observations.

Rejected or clamped requests - a disabled tab, an out-of-range page - are normalized back into the store. API calls are observed synchronously; events and attribute changes are coalesced into a microtask. Removing the element alone does not dispose the binding.

Benchmarks

📈 How it scales, measured

One operation, timed while its input grows: deeper paths, longer lists, more subscribers. A path is parsed and walked segment by segment, a write copies each object and array on its path, and a commit visits every subscriber. So each cost grows with what it touches and with nothing else; the charts show by how much. Persistence encodes the whole stored value on every write, so its cost follows the stored size: keep large, fast-changing lists out of persisted stores, or split them.
